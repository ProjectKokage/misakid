# Porting Status

Last reviewed: 2026-07-22

Root Dart package version: 0.1.0. The `misakid_mecab_ja` sibling is also 0.1.0;
the other optional adapter packages remain independently versioned prereleases.

Misakid is a behavior-preserving Dart port of Misaki under active pre-1.0
development. Exact committed fixtures cover both English dialects, Japanese
number and pyopenjtalk-style rendering, Korean default mode, and both Chinese
frontends. Supported vertical slices now include Japanese pyopenjtalk,
Japanese Cutlet, Korean g2pkc-default, English small-model plus eSpeak on
macOS arm64, pure-Dart English small-model without fallback, English
transformer no-fallback/eSpeak on macOS arm64, and pure-Dart Chinese legacy,
frontend-1.1-without-English, and the exact frontend-1.1 plus
small-model/no-fallback English callback profile on Dart VM platforms. Every
slice requires its documented explicit pinned resources.
Consult the precise matrix below rather than advertising broad “Misaki
parity.”

Both Japanese backends now have first-class mobile implementations. Their
Android/iOS native-assets build profiles share one repository-owned Flutter
harness, while Cutlet also supplies the default Kokoro frontend handoff. A
complete three-ABI Android release bundle and an unsigned iOS arm64 device app
contain both verified native assets. Cutlet's exact fixture passes on Android
15/API 35 arm64 and iOS 26.4 emulated runtimes; Open JTalk's exact fixture
passes on Android 15/API 35 arm64 and an iOS 26.5 Simulator. Mobile release
tuples remain experimental until physical-device and clean hosted-matrix
validation pass. Both supported macOS-arm64 tuples are unchanged.

## Status meanings

- Unsupported: not exposed as a documented public Dart configuration and not
  covered by exact committed fixtures.
- Experimental: implemented behind an explicit experimental contract, with
  known parity or platform gaps documented.
- Supported: satisfies every support condition in AGENTS.md, including exact
  parity, typed backend failure, documentation, and clean quality checks.

Experimental components are useful for integration and further parity work,
but are not complete supported language configurations.

## Requirements before any mode changes status

A mode remains unsupported until its public configuration and backend limits
are documented, representative and adversarial fixtures from the pinned
Python reference are committed, exact phoneme and token comparisons pass,
backend failures are typed and actionable, and formatting, analysis, tests,
and applicable publish checks pass. An implementation without those items is
not sufficient to change this table.
